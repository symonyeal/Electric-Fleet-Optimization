# Electric Fleet Optimization

This repository implements optimization models for electric delivery routing and bus
scheduling with charging constraints. Its results include certified optima or bounds on
seven IEEE WCCI-2020 routing instances and models of TransLink Route 100's 219 daily trips.
With battery limits ignored, 16 buses cover the timetable; the full-day battery-constrained
case has not been computed.

## Methods and applications

The IEEE WCCI-2020 competition report lists its EVRP values as upper bounds that "could be
optimal in some cases but [are] not verified yet." Later heuristics, including
[evrp-python](https://github.com/NeiH4207/evrp-python), report shorter routes on six of the
seven small instances; they do not report lower bounds. This project solves the benchmark
MILP where possible and uses column generation to bound instances it cannot solve directly.
The table above distinguishes certified results from open bounds.

TransLink publishes Route 100's timetable as GTFS. Given the trips and declared battery,
charger, and grid parameters, the transit models calculate the buses and chargers needed
and their cost, from a battery-free fleet bound to a convex MINLP with charging losses.

## Interior-point methods

They solve continuous problems; integer decisions still need branch-and-bound,
decomposition, or outer approximation. Here they supply LP bounds at inexact
branch-and-bound nodes, well-centered duals for column generation, and barrier
solutions of the convex charging subproblems inside outer approximation. The
mathematics follows Vanderbei, *Linear Programming* (4th ed., 2014), and Beck,
*Introduction to Nonlinear Optimization* (2014).

## Scope

Small instances. One depot, homogeneous vehicles, no time windows, no driver duties,
no distribution-network power flow. Benchmark distances are unitless. The Route 100
scenarios price energy with BC Hydro's published fleet tariff and take the pack,
consumption, charging efficiency and charger count from published sources; charger power,
the depot and the capital costs remain declared, not agency data ([Data](docs/DATA.md) §3). It does not reproduce TransLink
dispatch, authorize infrastructure, or match the speed of VROOM, PyVRP, or HiGHS.

## Run

Python 3.14 with numpy, scipy (HiGHS 1.12) and matplotlib, and stable Rust for the two
kernels that profiling moved there ([Design](docs/DESIGN.md) §9): ng-route pricing and the
interior-point iteration. `data/evrp.py` fetches the benchmark from evrp-python at a pinned
commit and checks its SHA-256.

```text
python -m pip install -r requirements.txt
python -m pip install --no-build-isolation .     # builds the module efo from crates/
python -m pytest -q -m "not slow"                  # the checks of Validation §2
python run_case.py evrp E-n22-k4 R1 --time 600     # R0 | R1 | R1-TR | R2-ipm | R2-simplex
python run_case.py transit route100 M1 --until 8   # M0 | M1; --until H cuts the day at H:00
python run_case.py transit route100 M1 --scenario rs1640   # sourced parameters (Data §3)
python run_bench.py                                # tables, figures and the block above
python run_bench.py --grid                         # first recompute the charging-physics grid
python run_baseline.py E-n22-k4 --repo PATH        # evrp-python's GSGA, replayed
```

Each run writes a bundle to `docs/results/`: status, U, L, gap, solver message, time,
code revision, data and kernel checksums and parameters, with the replayed routes or schedule.
A bundle supports a verdict only after the result contract admits it ([Validation](docs/VALIDATION.md)).
`methods/native.py` refuses a kernel module built from other sources. GitHub Actions runs the
Rust checks, the fast suite and the pinned-EVRP-data tests on every push; the GTFS snapshot,
which cannot be fetched again, and the slow experiments are local checks.
